EMULATOR BRIDGE
2.1.1

INTRODUCTION.

The bridge is the only path to the emulator. It binds loopback only, refuses every request that does not carry its token, and exposes thirteen operations. A session without the token cannot talk to the emulator at all (figure 2.1-1).

2.1.2

FUNCTIONAL DESCRIPTION.

Every caller presents the token; the guard compares it in constant time and refuses the rest. Operations are line-delimited requests on one socket or single commands. Game access is serialised: one call at a time, so a console viewer and an agent cycle queue rather than corrupt the emulator.

2.1.2.1

Serialisation.

An unbounded thread per connection once drove the host to load 1016. The bound now caps concurrency and Game access is a lock, so one slow frame makes everything wait its turn rather than fight.

2.1.2.2

One Socket Or One Command.

A live session speaks line-delimited requests on one socket; everything else sends single commands. When one Game call stopped answering it held the bridge for 25 seconds and every panel starved; the bound now makes one slow frame cost itself only.

2.1.2.3

Revocation.

The bridge refuses to boot without a token file, so it cannot start naked by accident. Revoke by killing the process and deleting the token; enable per session.
