RAM READER
3.1.1

INTRODUCTION.

The RAM reader is System One's eye. It reads the emulator memory directly: map, player tile, facing, party, collision, and the sprite state table. It renders the room as a 10 by 9 tile grid with the player's facing arrow in his own cell (figure 3.1-1).

3.1.2

FUNCTIONAL DESCRIPTION.

Terrain comes from the ROM tile table; sprites come from wSpriteStateData1 at address C100, sixteen records of sixteen bytes, the player in slot zero. Facing renders as an arrow. The grid is the reference the vision channel is judged against, and its own terrain labels measured 83.6 percent against ROM collision.

3.1.2.1

Reference, Not Truth.

The reader is a reference, not an oracle. Sprite meaning, dialogue and menus are invisible to it. A verdict disagreement is a finding to investigate, never a reason to overwrite one channel with the other.

3.1.2.2

What The Reader Cannot See.

Text, menus, dialogue and name entry are invisible to RAM. A sprite's meaning is not in memory either. An out-of-range cell answers walkable, so read the code before trusting a verdict row that says the way is clear.

3.1.2.3

Cost.

The read is free and runs every cycle, which is exactly why it is the reference channel and the vision model is the guest that must justify its 25,000 tokens.
