SYSTEM OVERVIEW
1.1.1

INTRODUCTION.

AI-PLAYS-POKE is an agent that plays POKEMON BLUE by understanding each room. It perceives through two channels, RAM and a vision model, that must agree cell for cell in one grid and one legend; JEV decides most cycles and hands the state to a reasoning model only when it cannot decide (figure 1.1-1).

1.1.2

FUNCTIONAL DESCRIPTION.

The emulator advances only when the bridge delivers inputs, so a live ticker stands in for a paused hand-held. The operator watches and drives through the console; the agent runs through the same bridge, and the two never drive at once. The fleet builds, tests and releases the agent; the board and the judge keep its work honest.

1.1.2.1

State Of The Goal.

The September run reached VIRIDIAN CITY in 28 episodes. The October 27 run stopped the morning it started: 4 episodes, the last inside RED'S HOUSE 1F. The machine has improved; the game has not advanced since (measured 2026-11-11).

1.1.2.2

The Fleet Around It.

Ten lanes serve this project: a foreman at priority 10 on a six-hour pin, plus qa, sync, releng, docs, readme, review, perf and their satellites. Since September 28 the foreman has landed 60 commits; the board holds 357 rows, 339 complete. The lanes share this host and its free-model quota with the emulator.

1.1.2.3

What Is Deliberately Absent.

No story modelling, no scripted walk tables, no voice control. The agent must win by understanding; everything else is scaffolding and is described only as it serves that.
